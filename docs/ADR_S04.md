# S04 architecture decisions and deviations (Download Bridge v1, PROPOSED shapes)

This file records the implementation decisions of the S04 v01 candidate. Architect decisions S04-D01 to S04-D10 are honoured. Every place where a shape differs from S01 v03 06 is listed here.

## 1. Decisions

| ADR | Decision | Reason | Architect action |
|---|---|---|---|
| ADR-S04-01 | **Additive migration `0003_download_bridge.sql`.** It creates 8 append-only tables with immutability triggers, FK/UNIQUE/CHECK constraints and 4 enforcing triggers. 0001 and 0002 are byte-identical. As a direct consequence, 8 schema-version literals in accepted tests were adapted (`docs/S04_TEST_ADAPTATIONS.md`) | The bridge needs FK-bound, append-only records in the same transaction scope as S03 asset registration, so that crash recovery and idempotency hold. A side database or untracked files would weaken backup completeness (S03-F02) and referential integrity | accept the test adaptations (precedent: S02 tests adapted in S03) |
| ADR-S04-02 | **Bridge-owned CAS references.** The KB stores the manifest bytes and the PBD input CSV bytes in CAS, as `bridge_batch.manifest_bytes_sha256` and `bridge_batch.input_csv_bytes_sha256`. Both are listed in `CAS_REFERENCE_COLUMNS` for schema ≥ 3, so doctor, create/verify/restore backup and upgrade all enumerate them (S04-D08). Result CSV bytes are **not** stored: they may contain local paths and URLs. Only their SHA-256 and whitelisted, sanitized fields are stored | Independent persistence of what was exported; no second CAS layer | none |
| ADR-S04-03 | **Files enter only through S03 `AssetService.register_asset`** (G0–G3), always with `require_human_identity=True`. A bridge file is therefore at most UNVERIFIED/AMBIGUOUS until a human review. The PBD-reported `file_path` is never opened: the file is looked up as `<pdf-folder>/<save_as>` | S04-D06, B-INV-5 | confirm that bridge files never auto-match |
| ADR-S04-04 | **DocumentVersion `UNKNOWN`** (one per paper, reused). Neither a PBD download nor a URL is version evidence (DV-1) | S01 05 DV-1 | none |
| ADR-S04-05 | **Source checks.** The Stage-11B checker re-implements every portable check of Reprovane 2.0.1 `verify_export` except the policy digest. Its manifest digest equals the native result on the native fixture. Native `verify-export` output can be supplied and is cross-checked (`--rv-verify-json`). Stage-11 sources use the accepted S03 strict reader | No Reprovane import at runtime; the hash only says the files are self-consistent, nothing about who made them | decide whether native verify output should become mandatory |
| ADR-S04-06 | **Stricter path rules for bridge arguments** (`guard_path_text`) than the S02/S03 core. Refused everywhere: drive-relative `C:x`, `..`, `:` (alternate data streams), reserved device names, trailing dot/space, NUL. Core rules still apply (UNC/device, foreign host, links, protected root). The S02/S03 core behaviour is unchanged | The S04 prompt asks for refusal of ADS, reserved names and traversal. The core accepts `C:x` on Windows, and `safe_data_root('CON')` raised a raw OSError | consider moving these rules into the core in a later stage |
| ADR-S04-07 | **PBD compatibility profile `pbd-csv-v1`**, pinned to V5.2.11 at `2901b046` (CsvUtils.cs blob `3d4e607f`). Any other header is `HEADER_MISMATCH`; any other status is `UNKNOWN_STATUS` (quarantined) | S04-D10. The architect's orientation file names blob `dfda3180` (a newer main); compatibility with it is **not** assumed | supply a reviewed profile for a newer PBD |
| ADR-S04-08 | **Exit code 4** (partial) whenever any anomaly exists: missing, unexpected, duplicate or malformed rows, extra files, unknown status, quarantine | S01 06 §10 | none |
| ADR-S04-09 | **WRONG_BATCH** when fewer than half of the data rows match the batch's `save_as` set (S01 06 §9 #16). The whole file is refused | contract | none |
| ADR-S04-10 | **Crash resume.** Every write is keyed (UNIQUE semantic hashes; one file event per attempt). A re-run continues where the previous run stopped, and the batch-level journal row is written last. Resumed facts equal those of an uninterrupted run (test S04-IMP-CRASH) | S01 06 §8 | none |
| ADR-S04-11 | **(v02, S04-F01) Numeric and internal hosts are never exported.** `policy.url_refusal` is purely lexical (no DNS, no socket call). Order: scheme → userinfo → any `[`/`]` in the authority (`URL_IP_LITERAL_REFUSED`) → port / authority mismatch (`URL_AUTHORITY_REFUSED`) → canonical `ipaddress` literal (`URL_IP_LITERAL_REFUSED`) → host characters outside `[a-z0-9._-]` (`URL_HOST_CHARACTERS_REFUSED`) → `numeric_host()` (`URL_NUMERIC_HOST_REFUSED`) → single label, trailing dot or reserved suffix (`URL_LOCAL_HOST_REFUSED`) → fragment → signed URL. `numeric_host()`: after one trailing dot, the last label is all digits or `0x`+hex, **or** any label is `0x`+hex. This is a superset of what WHATWG URL parsers (Chromium/WebView2, which PBD uses) and inet_aton-style parsers read as IPv4, so mixed decimal/octal/hex forms are covered without re-implementing either parser. A refused URL is omitted (row flag), never rewritten; a later safe candidate of the same item is still exported as itself | A false negative hands a loopback/private target to a logged-in browser; a false positive only leaves a cell empty for a human to fill. No real DNS name ends in an all-digit label (no numeric TLD); the only cost is a rare `0x…`-labelled DNS name | none |
| ADR-S04-12 | **(v02, S04-F02) Bridge path guard order.** `guard_path_text`: invalid/NUL → drive-relative `X:` without a separator (`DRIVE_RELATIVE_PATH_REFUSED`, every OS) → protected root on the raw text and on `os.path.abspath(text)` (`PROTECTED_DATA_ROOT`, lexical, before any stat) → core `refuse_unsafe_path_text` (UNC/device `UNSUPPORTED_PATH_FORM`; on POSIX absolute Windows or backslash paths `WINDOWS_PATH_ON_POSIX`) → `:`/ADS, `..`, reserved names. Core S02/S03 path code is unchanged | One stable code per form across OSes; the S04 bridge never stats the protected root | none |

## 2. Deviations from S01 v03 06

| # | S01 06 element | S04 implementation | Why |
|---|---|---|---|
| E1 | Manifest `source.workspace_ref` | `workspace_semantic_sha256` (the workspace ID is kept in the KB row) | IDs and local labels are not portable facts |
| E2 | `rkb bridge export --kind legacy-manual` | not implemented (optional adapter; documented gap) | No pinned legacy schema in scope |
| E3 | `is_open_access`, `oa_status` cells | left empty | Manual-queue rows carry no OA claims; the corpus `oa_locations` are not re-interpreted |
| E4 | `publisher` cell | empty; `source` = first venue claim | Display only |
| E5 | `rv-corpus` URLs | no direct URLs (flag `NO_RV_ELIGIBILITY_DECISION`); DOI and landing page only | Stage-11 has no RV eligibility decision; a direct URL is never exported without one |
| E6 | Additional row flags | `PAPER_ALREADY_IN_BATCH`, `DOI_SOURCE_KB_MISMATCH`, `DOI_NOT_VALID_IN_KB`, URL refusal codes, display sanitation flags | Transparency |
| E7 | DOI cell | the KB's ACTIVE `comparison_key`, required to equal the RV value exactly (lowercase ASCII only); `/` inside the suffix is suppressed (04 §4.7 strict) | No silent rewriting |
| E8 | Bridge status `QUARANTINED` | added for `ROW_IDENTITY_MISMATCH` and `ROW_DUPLICATE` rows | 06 §8 says "quarantined" without naming a status |
